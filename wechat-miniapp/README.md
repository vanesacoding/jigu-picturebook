# 叽咕插画 · 微信小程序源码

把今天的小故事，画下来。

这是原生微信小程序 + CloudBase 云函数项目。家长使用自己的微信身份登录；豆包凭据和预算归运营方，不让家长配置 Key。尚未部署成可扫码体验的小程序，页面中没有假付款、假生图或假的用户书架。

## 产品决定

- 使用第三版的小书架视觉，记录页采用清晰的单页表单；字体与「叽咕一下」同源，详见 [文字规范](docs/typography.md)。
- **按本收费**：首次免费 1 本 5 页小书；之后 5/7/10 页分别 ¥3.9/5.9/7.9，含封面，每本含 2 次主动单页重画。失败恢复与主动重画分开；每页累计最多 4 次模型请求，避免无限扣费。
- 家长看“免费一本”“赠送一本”“购买一本”，不需要理解画笔余额。
- 首页和书架均有“叽咕其他产品”。英语绘本 AppID 未配置时，明确提供复制现有网页版地址；配置后直接跳转小程序。
- 后台预留签名赠书接口，未来支持阅读活动引流；**尚未接入阅读达标判定或自动发奖**。

## 已实现的源码

8 个原生页面：做小书首页、记录、确认、后台生成进度、翻阅、私有书架、订单、叽咕其他产品。支持 1–6 张照片、上传前 canvas 去 EXIF 和压缩、服务端再次规范化、原文草稿本地恢复、上传后书籍云端保存、5/7/10 页编辑、逐页任务、独立失败恢复、原图/新图选择、文本修改、PDF、删除关联图片。

后台以可信 `OPENID` 校验每一次读写和图片 URL 请求；客户端不能直接访问数据库/存储。图片签名 URL 有效 10 分钟，不用于公开分享，泄漏后在失效前仍可能被持有者访问。原始 API Key、支付私钥均不进入前端。

首次免费名额、订单状态和生成任务使用数据库事务；付款以服务端签名验证回调/主动查询为准，客户端 `requestPayment` 成功不能触发生成。后台定时任务继续绘画，不依赖家长停留页面。退款提供受保护的运维接口，未交付订单可以发起退款，处理中状态通过受保护的 `refundStatus` 运维操作向微信查询核实。

## 本地检查

需要 Node.js 20.19+ 和 Python 3。根项目测试只用 Node 内置库，不调用任何真实收费接口。

```bash
npm run check
npm test
npm run build:cloud
```

然后在**微信开发者工具**导入本目录，选择小程序项目。`project.config.json` 的 `touristappid` 只用于源代码查看，不能获得真实 CloudBase OPENID 或上线。真实开发必须替换自己的 AppID、填入 `miniprogram/config.js` 的 `envId`，并关联云环境。

源码检查不是微信编译器检查。本环境没有微信开发者工具、AppID、云环境和商户凭据，因此尚未完成原生编译、扫码真机、真实支付/退款和真实豆包五页验收。

## 私有部署顺序

1. 准备已认证小程序、CloudBase 环境，绑定 AppID。填写 `project.config.json` 和 `miniprogram/config.js`，不往客户端加任何密钥。
2. 建立集合 `users / books / jobs / orders / grants / ledger / control / deletions`。**每个集合**配置 `docs/database-security.json`；云存储配置 `docs/storage-security.json`，同时确保 COS 桶没有公开读策略/CDN。不要仅上传规则文件而未在控制台实际启用。
3. `npm run build:cloud`，在开发者工具对四个云函数选择“上传并部署：云端安装依赖”。依赖包含 sharp，必须在 Linux 云端安装，不能上传 macOS 编译产物。运行时 Nodejs20.19，generator 超时 120 秒、内存 512MB，其余 60 秒。
4. 控制台应用 `docs/function-security.json`，只开放 `api` 给登录客户端。**generator、ops 禁止客户端调用**。generator 的分钟定时触发器需单独上传/创建，名称 `jiguBookQueue`，七字段 cron `0 */1 * * * * *`。不要把 generator 暴露成公网 URL。
5. 按 `docs/server.env.example` 在服务端配置环境变量。ARK 预算/收费调用默认关闭。验证真实账户的图像模型权限后，获得运营方测试预算，再设置 `ARK_PAID_ENABLED=1`、`ARK_TOTAL_BUDGET_CNY`。没有文本模型时会明确显示“原文初稿”，不会假装调用 AI。
6. 只有 payNotify 配置签名校验的 HTTP 回调入口；普通事件函数通过 HTTP 接入使用平台执行角色权限。若选择 Web/HTTP 云函数，平台不注入管理凭据时须单独配置服务端 CloudBase API Key，不得把 API Key 放入小程序。回调原始 body 不能被中间件重新序列化。
7. 绑定微信支付商户，配置 APIv3 对称密钥、商户私钥/证书序列号、微信支付公钥与公钥 ID、通知地址。**先确认经营类目与该数字内容服务适用的支付产品、各设备限制**，再开启 `WX_PAYMENT_ENABLED`。普通 JSAPI 适配器不等于已具备全部设备/类目收款资格；当前 iOS 购买默认关闭，尚未实现虚拟支付适配器。不能用更改前端平台值绕过规则。
8. 微信后台填写隐私保护指引、第三方处理方、保留期限、运营方联系方式，声明照片选择/处理用途。配置必要的 CloudBase/COS 下载域名和客服，配置“叽咕一下”AppID/跳转路径。临时 URL 域名必须允许 native image 和 wx.downloadFile 读取。
9. 先体验版：两账户互访拒绝、照片 EXIF、手机刷新/重启恢复、后台任务、失败恢复、PDF 中文、支付/退款联调。云规则需在真实环境测试。全流程通过后再提审；本项目不会自动公开发布。

## 生成与预算

生图服务唯一适配器为方舟 `images/generations`，模型 `doubao-seedream-5-0-flash-260915`；参考原始照片 Base64，1776×2368、watermark:false、b64_json。收到尺寸不符或远端结果不明确时保留已有页面、标记 uncertain，不自动重复请求。

价格不是已验证毛利。默认图像预算预留 ¥0.12/次、文本 ¥0.05/次，5 页约预留 ¥0.60；2 次重画另预留 ¥0.24。全局 `control/spend.reserved` 是**累计保守预算占用**，失败/超时不会自动释放以防重复费用，不是财务实扣账单。`ledger` 保存 usage、耗时和估算；当前实际模型花费 ¥0，未测真实生成时间。配置后须按方舟最新实际账单校正单价；运维对账后人工提高总预算，不要随意清零。

单环境并发 1 页，定时任务每分钟拉起，只在前 40 秒内启动新页，为最长 50 秒图像请求和存储留出超时余量；全局锁租约 210 秒。性能适合小规模验证，正式面向大量家长前需要增加有界队列并发及监控。每页实际费用调用次数与时间只在真实测试后报告。

## 阅读活动赠书

只允许内部服务签名调用 ops 的 `grant`，HMAC-SHA256 数据为 `source\neventId\nopenid\ntimestamp`，时间窗口 5 分钟；同一活动事件只发一次 5 页赠书名额。source 仅 `jigu-reading`/`ops`。

**不同小程序的 OPENID 不相同**：英语产品必须先通过同一开放平台 UnionID 的受信映射，或一次性签名兑换凭证，将目标关联到插画产品的 OPENID，再由服务端发放。不能直接拿英语产品 OPENID 发放。当前没有上线跨产品账号关联、活动页或奖励门槛，前台不承诺已发放。
